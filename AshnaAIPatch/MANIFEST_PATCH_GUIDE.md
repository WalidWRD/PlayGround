# دليل باتش المانيفست + التثبيت بدون روت (LSPatch / NPatch / HKP)

> Xposed Runtime لا يستطيع تعديل المانيفست — هذا الدليل لخطوة إعادة التغليف فقط.
> الحالة الحالية (AshnaAI 1.0.6): لا توجد عناصر إعلانية في المانيفست — لا شيء يُزال الآن.
> احتفظ بهذا الدليل للإصدارات القادمة إن ظهرت عناصر إعلانية.

## 1) عناصر تُزال عند ظهورها في إصدار آخر
- الأذونات: com.google.android.gms.permission.AD_ID / com.google.android.gms.ads.APPLICATION_ID (meta-data) / ACCESS_ADSERVICES_*
- المكوّنات: أي Activity/Service/Receiver/Provider يحمل في اسمه Ads / AdView / AdActivity / AdService / INSTALL_REFERRER المرتبط بالإعلانات
- الأداة: Apktool أو NPatch manifest editor — احذف العنصر ثم أعد البناء

## 2) التثبيت بدون روت (App) — الخيارات
### أ) LSPatch Manager
1. ثبّت LSPatch Manager الرسمي
2. أضف حزمة AshnaAI الأصلية + موديول AshnaAIPatch APK (ملف app-debug.apk المبني هنا)
3. باتش -> ثبّت الناتج -> افتح التطبيق المُرقَّع وفعّل الموديول من داخله
### ب) NPatch
1. افتح NPatch -> اختر AshnaAI APK -> أضف الموديول
2. (اختياري) عدّل المانيفست حسب القسم 1
3. باتش وثبّت (قد يتطلب إلغاء تثبيت النسخة الأصلية لتضارب التوقيع)
### ج) HKP Patch
- نفس خطوات LSPatch: دمج الموديول داخل الحزمة ثم التثبيت كتطبيق عادي

## 3) ملاحظة PairIP المهمة
- إعادة التوقيع بعد أي تعديل حزمة قد تُفعّل LicenseActivity (رفض العمل) — هذا سلوك حماية التطبيق وليس خلل الموديول
- الموديول نفسه Runtime فقط ولا يعدّل الحزمة ولا يمس فحص الترخيص — أي شاشة ترخيص تظهر بعد الباتش سببها إعادة التوقيع

## 4) التحقق بعد التثبيت
- LSPosed log / LSPatch log يظهر: AshnaAIPatch ... All hooks installed safely
- افتح التطبيق: حوار التحديث يُغلَق تلقائياً + لا بانرات إعلانية + لا كراش
- إن ظهرت شاشة دخول/OTP طبيعية فالقائمة البيضاء تعمل (لا تبلغ عنها كخلل)
