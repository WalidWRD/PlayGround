# LOKTV Hook Pro — ملف التحليل والنتائج v2.1.0
**الغرض:** حفظ نتائج التحليل لعدم إعادة التحليل كل مرة. هذا الملف هو المرجع المعتمد للبناء والصيانة.
**التاريخ:** 2026-10-07 — **الإصدار:** 2.1.0 (210) — **الوسم:** 2026.10.07-r2

## 1) ملخص تنفيذي
- تم تحليل إطار مرفق من 42 ملفاً: 13 صنفاً تخص التطبيق الهدف + 29 صنفاً لمكتبة الهوك القديمة.
- الإطار القديم كان يعتمد على أسماء أصناف ثابتة ويستدعي المكتبة مباشرة، ما يجعله هشاً أمام أي تحديث/تشويش/ضغط.
- أُعيد بناء الموديول بالكامل على **lpparam.classLoader + انعكاس Reflection + فاحص dex شامل**، مع درع ضد الكراشات، وسجل تشغيل، وإعدادات ساخنة، ودعم صريح لـ **LSPatch / NPatch / HKP بدون روت**.
- v2.1.0 يضيف: إصلاح إعادة التطبيق على المحمّل الحقيقي، توسيع F02/F06/F10، وميزات جديدة **F15/F16/F17**، مع وصف مدمج محدّث يظهر في مدير الموديولات وسجل التشغيل.

## 3) نقاط الضعف التي أُصلحت (v2.0.0 → v2.1.0)
1. **أسماء ثابتة:** أي إعادة تسمية كانت تعطل الهوك → استُبدلت ببحث انعكاسي + فاحص شامل + fallback لعبث التشويش.
2. **مكتبة الهوك القديمة:** غير متوافقة مع Android 10+ → واجهة Xposed القياسية `82` التي توفرها أدوات الترقيع الثلاث.
3. **غياب حماية الكراش:** أي استثناء كان يسقط التطبيق → خطوات معزولة `Engine.step()` + فحص مصدر الاستثناء عبر كامل الـ stack (v2.1.0) + عدم ابتلاع أخطاء التطبيق نفسه.
4. **لا دعم للتطبيقات المضغوطة:** المحمل الأول وهمي → خطف `attachBaseContext/onCreate` + **إعادة تطبيق متعددة (حتى 3 محملات)** + إعادة محاولة متأخرة 1.5s/4s (v2.1.0). **إصلاح قاتل:** v2.0.0 كان يمنع إعادة التطبيق بسبب `sApplied` — أُصلح بمجموعة `sAppliedLoaders`.
5. **لا سجل ولا إعدادات:** أُضيف سجل مزدوج + إعدادات ساخنة + مفاتيح جديدة `ads_block/tracker_block/update_dialog` مع تحقق من `rotation`.
6. **تشفير الإعدادات المعقد:** لا حاجة لإعادة تنفيذه — الموديول لا يعتمد عليه.
7. **بوابات التحديث معكوسة القطبية:** `isForceUpdate/hasUpdate/needUpdate` كانت تُعالج كـ true بالخطأ → الآن **false** صراحة (v2.1.0).
8. **كشف ضيق:** أُضيفت كلمات `rooted/magisk/frida/emulator/safetynet/playintegrity/signature/verify` + معالجة `boolean->false` و `String->""`.
9. **فاحص عام محدود:** كان boolean فقط → الآن **boolean/int/long** (VIP level=9999، expiry=4102444800000) (v2.1.0).
10. **أداء الفاحص:** أُضيف cache لأسماء dex لكل ClassLoader + حد أقصى + تجاهل `android./java./kotlin./androidx.` في الـ fallback.

## 4) معمارية الموديول (تقبل التطوير والصيانة)
```
LokTvHook (نقطة الدخول: xposed_init)
  → isTarget() + attachBaseContext/onCreate + scheduleRetry()
  → Engine.apply(cl, pkg, ctx) [معزول، متعدد المحملات]
      → HookConfig.load() [ساخن، validated]
      → Features.userStatus()      F01-F05
      → Features.antiDetect()      F06
      → Features.antiVpn()         F07
      → Features.floatingView()    F08
      → Features.rotation()        F09
      → Features.genericScanner()  F10
      → Features.adsBlock()        F15 (جديد)
      → Features.trackerBlock()    F16 (جديد)
      → Features.updateDialogBlock() F17 (جديد)
      → Features.crashGuard()      F12
      → ClassScanner / Reflect / Log / ModuleInfo [خدمات]
```
- **لإضافة ميزة:** أضف دالة في `Features.java` + مفتاح في `HookConfig.java` + استدعاء في `Engine.java` + سطر في `ModuleInfo.FEATURES` + توثيق هنا. لا تلمس طبقة الانعكاس.
- **البناء:** `bash build.sh` واحد (javac→d8→aapt2→zipalign→apksigner v1+v2+v3).

## 5) الإصدارات الأعلى والأقل + المضغوط/المحمي + بدون روت
- لا يوجد اسم صنف نهائي واحد: الاسم المعروف → أسماء بديلة → بحث بالاسم المختصر → فاحص dex → fallback غير مفلتر (للمشوّش).
- الفاحص العام يربط أي دالة منطقية بلا وسائط باسم يشبه VIP/تعديل/VPN/إعلان بغض النظر عن الحزمة.
- يُبنى كـ APK قياسي (`xposedmodule=true`، `xposedminversion=82`، `xposedscope`) + `assets/xposed_init` → يُرقّع به التطبيق الهدف داخل **NPatch / LSPatch / HKP** بدون روت. في المضغوط يُخطف المحمل الحقيقي من `attachBaseContext` وتُعاد الهوكات عليه (+ retry).

## 8) التركيب بدون روت
1. ثبّت APK الموديول على الجهاز.
2. افتح أداة الترقيع (NPatch/LSPatch/HKP) واختر تطبيق الهدف الأصلي.
3. اختر الموديول من القائمة ثم ابدأ الترقيع.
4. احذف الأصلية وثبّت المرقعة.
5. شغّل التطبيق وراجع السجل بالبحث عن `LOKTV-HOOK-PRO`.
6. لتعديل السلوك: حرّر `loktv_hook.conf` داخل مجلد files الخاص بالتطبيق ثم أعد التشغيل. المفاتيح: `vip,skip_update,valid_collection,video_data,disable_popup,anti_detect,anti_vpn,floating_view,generic_scanner,ads_block,tracker_block,update_dialog,rotation(-1/0/1),debug`.

## 9) الصيانة المستقبلية
- عند ظهور سلوك غير متوقع: ارفع `loktv_hook.log` + سطر `apply() done | hooks=.. | skipped=..`.
- لا تُضف أسماء ثابتة جديدة — أضف كلمات مفتاحية للقوائم POSITIVE/NEGATIVE/KEYS.
- حافظ على تزامن `ModuleInfo` ↔ `AndroidManifest` ↔ `loktv_module.json` ↔ هذا الملف في كل إصدار.
- ملاحظة: لم يُنفَّذ على جهاز حقيقي في هذه الجلسة؛ شمل التحقق: سلامة البناء + التوقيع + وجود الأصناف/الملفات.
