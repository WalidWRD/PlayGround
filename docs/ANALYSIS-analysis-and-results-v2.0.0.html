GenSubs UpdateKiller — ملف التحليل والنتائج ودليل البناء والصيانة

الإصدار 2.0.0 (build 200) · تاريخ الإعداد 2026-09-28 · هذا الملف مرجعي مختصر يجمع كل نتائج التحليل والقرارات التصميمية وخطوات البناء والدمج، حتى لا تُعاد التحليل في كل مرة. يعتمد على إصدارات 1.1.0 → 1.5.0 المرفقة ويضيف محرّك الإصدار 2.0.0.

الخلاصة التنفيذية في ثلاثة أسطر:
  1. منطق التحديث الإجباري لا يوجد في Java/DEX ولا في الطبقة الأصلية — كله في طبقة Dart داخل libapp.so (AOT snapshot)، لذلك تعديل النصوص الثنائية لا يُزيل الحوار.
  2. الحل الصحيح: اعتراض وقت التشغيل عبر موديول Xposed/دمج بدون روت، يستهدف نقاط القرار (الإصدار + حقول الفرض + فتح المتجر) لا النصوص.
  3. الإصدار 2.0.0 يرفع المناعة: فهرس أسماء الفئات من DEX الهدف + مطابقة بنيوية + تثبيت مُؤجَّل متعدّد المرور + اعتراض قنوات Flutter بـProxy — فلا أسماء فئات ثابتة، ويعمل على الإصدارات الأعلى والأقل وعلى الحزم المضغوطة/المحمية/المشوّشة.

2) موضع منطق التحديث (الحكم الجوهري) — نقطة القرار

لا يوجد منطق تحديث إجباري/فوري في الطبقة الأصلية ولا في DEX؛ كل المنطق في طبقة Dart داخل libapp.so (AOT snapshot). النصوص التالية استُخرجت بإزاحاتها:

وجود mine.appUpdate.later يثبت أن الحوار قابل للتأجيل إلا عند forceUpgrade=true. فتح المتجر يمرّ عبر قناة Flutter dev.britannio.in_app_review (LR8/b->onMethodCall تحمل openStoreListing وتبني رابط play.google.com/store/apps/details?id=)، والاحتياطي Lz5/f->a(...) ينشئ Intent market://details، وقراءة الإصدار في LW8/a وLV8/b.

لماذا فشل تعديل libapp.so وحده:
  1. النصّ بياناتٌ يعرضها كود مُترجَم، والشرط المُظهر للحوار في تعليمات ARM نفسها.
  2. تغيير طول أي سلسلة يُزحزح الإزاحات ويُفسد الـsnapshot → كراش.
  3. لا يمكن «حذف» Widget بتعديل ثنائي آمن.
الخلاصة: تستهدف نقاط القرار (تزوير الإصدار / إلغاء حقول الفرض / منع فتح المتجر) لا النصوص.

3) لماذا الموديول هو الحل الصحيح

تزوير PackageManager.getPackageInfo().versionCode في طبقة Java يُغيّر ما يراه Dart (قناة package_info تقرأ الحزمة من PackageManager عبر JNI)، فتصبح localVersionCode < minAppVersionCode غير محقّقة دائمًا مهما كان الإصدار — وهذا تجاوز محصَّن ضد تغيّر إصدارات التطبيق.

6) ضمانات عدم الانهيار

  1. Guard: كل عمل خطّاف داخل try/catch(Throwable) — لا استثناء يصل إلى التطبيق.
  2. Kill-Switch: بعد العتبة (افتراضي 20 فشلًا) تُعطَّل كل الخطّافات مع تسجيل تنبيه.
  3. لا setResult على دوال void: نتحقّق من نوع الإرجاع، وفي IntentHook نُعدّل كائن Intent في مكانه بدل إلغاء الاستدعاء.
  4. لا افتراض وجود فئة: غياب Flutter/Play Core/okhttp/إطار الدمج = تخطٍّ صامت.
  5. لا تعديل لملفات التطبيق ولا استهلاك شبكة (الاستثناء الوحيد: جسر الاشتراك الاختياري المعطّل افتراضيًا).
  6. Idempotent: كل صنف/مهمة تُربط مرة واحدة عبر مجموعات Set — فإعادة المرورات لا تُضاعف الخطّافات.

7) البناء والتحقق (المسار المستخدم في التسليم)

لا يحتاج الموديول أي مستودع خارجي: الـXposed API موجود كاستوب محلي في libs/xposed-api82/src. مسار البناء: aapt2 compile → javac → d8 → aapt2 link → zip (dex+assets) → zipalign → apksigner.

export JAVA_HOME=/path/to/jdk17
export BT=/path/to/build-tools/34.0.0
export ANDROID_JAR=/path/to/platforms/android-34/android.jar
export JAVAC=$JAVA_HOME/bin/javac
bash scripts/build_apk.sh
# OK → build/GenSubs-UpdateKiller-v2.0.0.apk

مهم: javac يحتاج -encoding UTF-8 (التعليقات العربية) والسكربت يتكفّل بذلك، ويُحظر استخدام show*/present* داخل تعليقات Javadoc لأن */ يُنهي التعليق.

أوامر التحقق

aapt2 dump badging GenSubs-UpdateKiller-v2.0.0.apk | head
apksigner verify --print-certs --verbose GenSubs-UpdateKiller-v2.0.0.apk
unzip -p GenSubs-UpdateKiller-v2.0.0.apk assets/xposed_init      # com.genspark.updatekiller.HookEntry
unzip -o GenSubs-UpdateKiller-v2.0.0.apk classes.dex -d verify/ && dexdump -f verify/classes.dex | grep 'Class descriptor'

8) الدمج بدون روت — LSPatch / NPatch / HKP Patch

LSPatch (سطر أوامر)

lspatch -m patch -o genspark_patched.apk genspark.apk GenSubs-UpdateKiller-v2.0.0.apk
adb install -r genspark_patched.apk
adb logcat -s GensparkUpdateKiller

NPatch (جافا)

java -jar NPatch.jar -m GenSubs-UpdateKiller-v2.0.0.apk genspark.apk -o genspark_patched.apk

HKP Patch (واجهة التطبيق)

  1. افتح HKP Patch → اختر التطبيق الهدف (Genspark).
  2. اختر الموديول: GenSubs UpdateKiller.
  3. اضغط Patch ثم ثبّت الـAPK الناتج (أعد التثبيت فوق النسخة الأصلية غير ممكن — يجب إزالة الأصلية أولًا لأن التوقيع يتغير).
ملاحظة توافق: الموديول يستخدم واجهة Xposed API 82 (متوفّرة في LSPatch وNPatch وHKP Patch وLSPosed)، ويصرّح بـxposedscope للحزمتين الافتراضيتين. لإضافة حزمة أخرى (نسخة مُعاد تجديدها): إمّا عدّل res/values/arrays.xml، أو — دون إعادة بناء — أضفها في packages: ["ai.mainfunc.genspark.xxx"] داخل ملف الإعدادات.

11) الصيانة والتطوير (لا إعادة تحليل)

  • خطّاف جديد: أنشئ hooks/XxxHook.java فيه public static int install(ClassLoader)، ثم أضفه كمهمة في HookEntry.registerTasks (وميِّز: أساسية فورية أم ديناميكية مؤجّلة).
  • بلا أسماء ثابتة: استخدم Discovery.classesByName / classesMatching / classesImplementing ثم Reflect.hookBySignature / hookWhere / hookByParamNames / hookByParamNames.
  • لتوسيع النطاق: BuildInfo.PACKAGE_NAMES أو مفتاح packages.
  • لتغيير الإصدار: عدّل BuildInfo + AndroidManifest.xml + res/values/strings.xml + اسم مخرج السكربت.
  • عند ظهور حوار جديد: لا تعدّل الـDEX — اقرأ ملف الأحداث لتعرف أي حدث ظهر، ثم وسّع NEUTRALIZE/OBSERVE في FlutterDiscoveryHook أو فئات UniversalGateHook، أو أضف مفتاحًا جديدًا في keys.

12) الملاحظات المؤكَّدة وغير المؤكَّدة

  • مؤكَّد بالتحليل الساكن: غياب أي منطق تحديث في DEX/الطبقة الأصلية · الإزاحات أعلاه · غياب SSL Pinning · غياب play.core.appupdate.* · وجود AdMob · سلامة بناء وتوقيع الإصدارات 1.1.0 → 1.5.0.
  • مؤكَّد آليًا في هذا التسليم: ترجمة كل المصادر وبناء وتوقيع GenSubs-UpdateKiller-v2.0.0.apk + وجود assets/xposed_init والوصف المدمج + سلامة الأصناف داخل classes.dex (نتائج الفحص في التقرير المرافق).
  • غير مؤكَّد — يحتاج جهازًا حقيقيًا: نجاح اعتراض الحوار على نسخة مثبّتة فعليًا، وتوقيت أول قراءة إصدار قبل بناء الحوار، ونجاح مسح libapp.so آنيًا. تُتحقّق بقراءة سطر ALL DONE … verdict=OK وتقرير JSON عند أول تشغيل.
