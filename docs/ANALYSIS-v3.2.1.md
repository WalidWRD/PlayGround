# LOKTV Hook Pro — ملف التحليل والنتائج v3.2.1
**الغرض:** المرجع المعتمد للبناء والصيانة (يغني عن إعادة التحليل).
**التاريخ:** 2026-10-08 — **الإصدار:** 3.2.1 (321) — **الوسم:** 2026.10.08-r5

## 1) نتيجة المراجعة الكاملة (ملفات v1 المرفقة + كل السورس)
- **جرد الـ zip:** نفس الـ 42 ملفاً المعروفة (13 صنفاً `com.novan.morpha` + مكتبة Pine `top.canyie.pine`) — القائمة المركزية فقط، لا جديد فيها beyond ما حُلل في v3.0.0. التفاصيل السلوكية مأخوذة من smali المقروء سابقاً (AntiVPN/FloatingView/GetRotation/UserStatus/VipItem/Hide*/LoadConfig).
- **فحص توافق الـ stubs مع Xposed API-82 الحقيقي:** كل التوقيعات المستخدمة (`hookMethod`, `findAndHookMethod`, `log`, `MethodHookParam`، `LoadPackageParam`) مطابقة ثنائياً — **لا يوجد خطأ ربط يفسر الصمت التام**. مع ذلك أُصلحت 3 فروق fidelity (انظر §2) للنظافة.
- **الاستنتاج:** الصمت التام + عدم ظهور حتى التوست يعني على الأرجح أن النسخة المختبرة **ليست v3.2.0** (ملفها لم يُعثر عليه) بل v3.1.0 التي بلا Toast ولا سلسلة retry. هذه النسخة تحمل كل إصلاحات v3.2.0 + التوست التشخيصي.

## 2) تغييرات v3.2.1 (مقارنة بـ v3.2.0)
1. `XC_Callback.java` جديد يطابق الهرمية الحقيقية (`XC_MethodHook extends XC_Callback`, `MethodHookParam extends Param`).
2. `XC_MethodHook.Unhook`: inner عادية ← `static` (مطابق للحقيقي).
3. `StartupParam.startsSystemServer`: boolean ← `String` (مطابق للحقيقي).
4. لا تغيير سلوكي مقصود — نفس الـ 21 ميزة ومنطق v3.2.0 حرفياً.

## 3) بروتوكول الاختبار المعتمد (إلزامي بعد كل بناء)
1. احذف أي نسخة قديمة من الموديول (اختلاف مفتاح التوقيع بين الجلسات).
2. ثبّت `LOKTV-Hook-Pro-vX.apk` مباشرة (بدون MT Manager).
3. في NPatch/LSPatch/HKP: اختر التطبيق الهدف + الموديول ورقّع وثبّت المرقعة.
4. شغّل التطبيق: **يجب ظهور توست `LOKTV Hook Pro vX | hooks=N`**.
   - ظهر ← الموديول يعمل؛ قارن N والحالة (VIP/إعلانات).
   - لم يظهر ← أعد الترقيع مع التأكد من اختيار الموديول (المشكلة تحميل لا هوكات).
5. أرسل: سطر `target detected ... [...]` + أسطر `Fxx => +N` + سطر `apply() done`.
